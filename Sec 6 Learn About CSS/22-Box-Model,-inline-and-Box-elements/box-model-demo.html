Companion to the box-model note. Inspect any box, then open DevTools → Elements → Layout (or the box diagram in Styles). That diagram is the ground truth for content, padding, border, and margin.

1. Four layers of a box

content (photo) → padding (mat) → border (frame) → margin (wall gap)

content
dashed pink = margin 24px cyan frame = border 8px gold fill = padding 20px green inner = content

Background paints through padding. Margin is transparent — it only pushes neighbors. Outline and box-shadow sit in the margin area visually but do not change layout size.

2. content-box vs border-box (same declared width: 300px)

width: 300px; padding: 20px; border: 5px solid; /* both boxes */

content-box outer = 300 + 40 + 10 = 350px (overflows a 300px parent)
border-box outer = 300px (content shrinks to 250px)

parent = 300px wide

content-box (default)

border-box

outer width 300px — fits

Inspect each .measure. content-box: width is a promise about the content only. border-box: width is a promise about the visible box (content + padding + border). Margin is never inside either formula.

3. display: inline vs inline-block vs block

same CSS on all three: width: 120px; height: 48px; padding: 8px 12px;

Text inline still flows inline-block then a block which took its own row.

inline ignores width/height — the chip is only as wide as the word. inline-block honors size and still sits in the sentence. block starts a new row (here it is narrower than the parent because width: 120px is set).

display is a seating policy, not a new element. The tags are still divs. Use inline-block when you need width/height/padding on items that share a line. (Modern navs often use flex; this is the CSS 2.1 pattern interviews still ask for.)

5. Inline → block (full-width clickable links)

a { display: inline } vs a { display: block; width: 100% }

default — links sit in the sentence

An <a> is inline by default. display: block makes the whole row clickable. Semantics stay "link"; only the layout contract changes.

6. Margin collapsing (adjacent block boxes)

.a { margin-bottom: 20px } + .b { margin-top: 30px } → gap is 30px, not 50px

box A — margin-bottom: 20px
box B — margin-top: 30px

collapsed gap between border edges = max(20, 30) = 30px

Vertical margins of adjacent block boxes in normal flow collapse. Does not happen between inline boxes, flex/grid items, or when a border/padding separates parent and child. Inspect A and B in the Layout panel — the gap between their border edges is 30px.
